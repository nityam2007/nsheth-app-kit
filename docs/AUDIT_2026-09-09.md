# Runtime, workflow and security audit — 0.9.1

## Scope and outcome

Investigated the reported null `useContext` error and stacked pages across admin/public routes, reviewed existing module workflows and access boundaries, and adapted the supplied Atelier source's navigation and task hierarchy. No browser, browser automation or screenshots were used, as required by RULES.md.

The owner's later instruction authorized dropping the local development database and required the development server to remain stopped. Project development processes and their children were stopped. Only local `nsheth_app_kit` was dropped/recreated; all 13 migrations and fresh sample data were applied. Production integration uses the separate disposable `nsheth_integration` database. No hosted database or deployment was changed.

## Verification

- Workspace formatting, ESLint, TypeScript and **39 unit/component tests** (including six non-browser component checks). Component regressions cover pagination, attention filtering and permission-aware navigation.
- Production build plus real server-function integration: anonymous/role isolation, CSRF, demo bootstrap disabled in production, module toggles, streamed-body limits, concurrent booking/stay capacity, adjacent stays, checkout idempotency and payload binding, stock limits/history, fulfilment, stale edits, retirement and conflicting admin changes.
- **81 production pages** rendered in-process after the UX changes, including public/admin/account collections, detail/edit/setup screens and status links; each had one main and one h1, with no error-page content. This starts no development server or HTTP listener.
- Development HTTP/auth checks passed before the requested shutdown. After a new VS Code dev session was detected, the complete final client crawl passed **63 pages** in the fresh sample workspace using actual Vite modules in Node VM/jsdom. Each retained one main, one heading and one optimized React instance, with no hydration/runtime errors. The audit did not start this server.
- Node and Cloudflare builds pass. Reset-target guards reject remote, production and unrelated database names. Watcher tests exercise atomic file replacement, burst coalescing and serial restarts without launching Vite.

## Limits

No pixel layout, browser interaction or final live HMR transport verification was performed. A new dev session was later detected under the owner’s VS Code terminal. It was left under their control and used for page verification without submitting domain forms; the audit did not launch dev after the stop instruction. Live email, GitHub OAuth, Stripe provider delivery and hosted deployment acceptance still require their configured environments. Zero known dependency advisories and passing tests are bounded evidence, not a guarantee that every possible defect is absent.

## Starting the updated workspace

Run `npm run dev` once. Open `/admin`, expand Development access if sign-in is needed, and select Use development admin. A previously open tab may need one full reload to discard old cached modules; subsequent edits use hot reload. See [local development](LOCAL_DEVELOPMENT.md) for reset and watcher behavior.
