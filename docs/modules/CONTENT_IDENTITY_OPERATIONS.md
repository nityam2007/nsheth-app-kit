# Publishing, identity and operator follow-up

## Planned journeys

Editors write structured articles with headings, lists and quotations; add author, cover/alt text, tags and search metadata; preview safely; schedule publication; recover prior revisions; and avoid overwriting another editor. Restoration creates a draft and a new revision so it cannot unexpectedly republish old material. Raw HTML remains text, never executable markup.

Operators search enquiries and privacy cases, claim responsibility, leave internal notes, set a follow-up date, change status with optimistic conflict detection and see an activity trail. Privacy status remains triage: it does not claim identity verification, data erasure or legal completion.

Account holders see active sessions and revoke other sessions. Administrators change access with serialized authorization revalidation, preventing concurrent cross-demotions from leaving no enabled administrator. Role changes revoke affected sessions and create audit records. Private response caching and client cache isolation must respect account boundaries.

## Acceptance and copy boundaries

Test scheduled invisibility, safe text rendering, stale post/triage updates, revision restoration to draft, cross-account session isolation and concurrent admin changes. Bound public and operator result sets, throttle public writes, and avoid returning internal notes or token hashes publicly. Use HTTP/database and unit tests, never a browser.

Copy domain schemas, server functions, routes, editor/history controls, Prisma models/migrations, identity middleware and audit helper. Email delivery, marketing automation, block page builders, enterprise SSO and automated legal/data-retention decisions remain destination-project integrations.
